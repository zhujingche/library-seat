## 二、踩坑记录（面试素材库）

### 1. `@TableName` 写错一个词，查错表 → 500

**现象**：请求返回 500，响应体只有 `{"status":500,"error":"Internal Server Error"}`，看不出原因。

**排查**：看控制台堆栈 →
```
### SQL: SELECT id,reservation_id,seat_id,reserve_date,slot_no FROM t_reservation WHERE ...
### Cause: java.sql.SQLSyntaxErrorException: Unknown column 'reservation_id' in 'field list'
```
**查的是 `t_reservation`（预约单表），不是 `t_reservation_slot`（占位明细表）。**

**原因**：`@TableName("t_reservation")` 少写了 `_slot`。

**教训**：
- **500 的响应体没用，真正的信息在控制台堆栈里**
- **读堆栈三步法**：① 找 `### Cause:`（是什么错了）② 找 `### SQL:`（实际执行了什么）③ 堆栈里找第一个 `com.zjc` 开头的行（你的代码哪一行）
- `@TableName` 是 Java 类和数据库表之间的**唯一约定**，写错就是查错表

### 2. Java 字段用下划线 → 数据映射成 null（静默失效）

**现象**：数据库里 `open_slot = 0`、`close_slot = 14`，接口返回却是 `"open_slot": null, "close_slot": null`。**不报错。**

**排查**：看 SQL 日志 → `SELECT id,name,location,open_slot,close_slot,status FROM t_room`，**数据查出来了（0, 14）**，但 JSON 是 null。**差在"塞进 Java 对象"那一步。**

**原因**：实体字段写成了 `private Integer open_slot;`。
MyBatis 的 `mapUnderscoreToCamelCase`（默认开启）会把列名 `open_slot` 转成 `openSlot`，然后去找 `setOpenSlot()` —— 找不到（实际是 `setOpen_slot()`），值就丢了。

**正确做法**：
```java
private Integer openSlot;    // Java 字段用驼峰
private Integer closeSlot;
```

**教训**：
> **数据库列名用下划线（`open_slot`），Java 字段用驼峰（`openSlot`），中间的转换 MyBatis 自动做 —— 但前提是 Java 那边必须是驼峰。**

### 3. Java 类型和数据库类型不匹配 → JSON 类型错

**现象**：`{"id":1,"roomId":"1","status":"1"}` —— `id` 是数字，`roomId` 和 `status` 却是字符串。

**原因**：`room_id` 是 `BIGINT`（应为 `Long`），`status` 是 `TINYINT`（应为 `Integer`），但都写成了 `String`。**MyBatis 自动做了类型转换，所以不报错。**

**教训**：**功能对了但类型错了，前端照样崩**（JS 里 `"1" !== 1`、`"1" + 1 === "11"`、字符串排序 `"10" < "9"`）。接口的类型契约必须严格遵守。

**类型对照表**：

| 数据库 | Java |
|---|---|
| `BIGINT` | `Long` |
| `INT` / `TINYINT` | `Integer` |
| `VARCHAR` | `String` |
| `DATE` | `LocalDate` |
| `DATETIME` | `LocalDateTime` |

### 4. 雪花 ID 与 `AUTO_INCREMENT` 计数器

**现象**：插入一条数据，`id` 是 `2109568900366594050`（19 位），不是 `4`。

**原因两个叠加**：
1. MyBatis-Plus 默认主键策略是 `ASSIGN_ID`（**雪花算法**），不是数据库自增 → 它自己生成了一个 19 位的 id
2. 后来改成 `IdType.AUTO` 也不管用 —— 因为**之前那批 19 位 id 把 MySQL 的 `AUTO_INCREMENT` 计数器顶了上去，而计数器只增不减**

**确认方法**：看 `INSERT` 语句
- `INSERT INTO t_user ( id, name, age )` ← **有 id** = MyBatis-Plus 自己生成的
- `INSERT INTO t_user ( name, age )` ← **没有 id** = 交给数据库自增

**修复**：
```properties
mybatis-plus.global-config.db-config.id-type=auto
```
并重置计数器：
```sql
ALTER TABLE t_user AUTO_INCREMENT = 4;   -- 前提：4 必须大于当前最大 id
```

**教训**：
- **`AUTO_INCREMENT` 计数器只增不减**，删数据不会让它回退
- **排查"id 不对"的问题，要看 INSERT 语句里有没有 id，不要看 id 长什么样**

### 5. `405 Method Not Allowed` = 代码改了没重启

**现象**：`PUT /user` 返回 405。

**原因**：IDEA 里改完代码后**没有完全重启**，运行的还是旧代码。IDEA 的"热重载"只能替换方法体，**新加方法、改注解它做不到**。

**教训**：
> **铁律：改完任何代码 → ⏹ 停止 → ▶ 启动。** 启动只要 2 秒，不值得赌。

**报错对照表**：

| 报错 | 含义 | 第一反应 |
|---|---|---|
| `Connection refused` | 对面没人 | **应用没启动** |
| `404` | 路径不存在 | 网址写错 / 接口没写 |
| `405` | 路径在，方法不在 | **代码改了没重启** |
| `400` | 请求数据它看不懂 | JSON 格式 / `Content-Type` / 缺参数 |
| `500` | 代码执行时崩了 | **看控制台堆栈** |

### 6. 参数名大小写不匹配 → 静默使用默认值

**现象**：`/user/page?pageNum=2&pageSize=2`，返回的却是第 1 页、每页 5 条。

**原因**：Controller 里写的是 `@RequestParam int pagenum, int pagesize`（全小写），而 URL 里是 `pageNum` / `pageSize`。
**URL 参数名是大小写敏感的。**

**教训**：参数名对不上**不报错**，直接回退到 `defaultValue`。这类"静默失效"只能靠**看实际输出**发现（SQL 里参数是 `5` 而不是 `2`）。

---

### 7. 分页插件没装 → 静默返回全部数据

**现象**：调 `selectPage`，返回了全表数据，**不报错**。

**原因**：MyBatis-Plus 默认不会分页。必须配 `PaginationInnerInterceptor`，并且引入 `mybatis-plus-jsqlparser`（3.5.9+ 拆成了独立模块）。

**教训**：**又是"不报错但结果错"**。分页必须验证 SQL 里出现了 `LIMIT` / `COUNT`。

### 8. 业务逻辑的四个经典错误

写"提交预约"时一次踩了四个，全是**想清楚逻辑**的问题：

| 错误 | 具体 | 教训 |
|---|---|---|
| **条件写反** | `startSlot < endSlot` 被写成"非法"（其实这是合法范围） | **先写"合法条件"，再整体取反**：`boolean valid = ...; if (!valid) throw` |
| **边界差一** | 循环写 `i <= endSlot`，多占一格 | **区间 `[start, end)` 的循环永远是 `i < end`** |
| **取值取错对象** | 预约单存了 `room.getOpenSlot()`，应该存 `req.getStartSlot()` | 变量名相似时要特别小心（`openslot` vs `getStartSlot()`） |
| **漏设字段** | 忘了 `setUserId()`，而 `user_id` 是 `NOT NULL` | 对着表结构逐列检查 |

**方法：手算一遍法**

> 写完一个方法，**别急着运行**。拿一组具体数字，**在纸上走一遍代码**：
> ```
> 假设 openSlot=0, closeSlot=14, startSlot=8, endSlot=12
> 第 43 行：0 >= 8 ? 否
>           14 <= 12 ? 否
>           8 < 12 ? 【是】 → 抛异常 ❌ 发现了！
> ```
> **30 秒就能抓到，比"运行 → 看 500 → 猜"快十倍。**

### 9. 两层校验：参数层 vs 数据层

**不要只检查一种 null**：

```java
// ① 参数层：客户端有没有传这个字段
if (req.getSeatId() == null) throw ...;

// ② 数据层：查出来有没有这个东西
Seat seat = seatMapper.selectById(req.getSeatId());
if (seat == null) throw ...;      // ← 少了这一句，传个不存在的 id 就 500
```

**教训**：客户端传 `{"seatId": 999}` —— 参数不是 null，但库里没有 999 号座位。**两层都要查，报错信息也要区分。**

### 10. `@Transactional` 里 catch 了必须 rethrow

**这是事务最容易踩的坑。**

```java
@Transactional
public Long makeReservation(...) {
    reservationMapper.insert(r);          // ① 插预约单
    try {
        for (...) { slotMapper.insert(s); }   // ② 插明细，可能抛 DuplicateKeyException
    } catch (DuplicateKeyException e) {
        // ❌ 如果在这里吞掉异常（只打印不抛），事务【不会回滚】
        //    ①② 会被提交，留下"只占了一半格子"的脏数据
        System.out.println("冲突了");
        return null;
    }
}
```

**正确**：
```java
    } catch (DuplicateKeyException e) {
        throw new RuntimeException("该时段已被预约了，请换一个");   // ✅ 必须抛出去
    }
```

**教训**：
> **`@Transactional` 是靠"异常往外抛"来触发回滚的。**
> **在事务方法里 catch 了却不抛出去，等于告诉 Spring "一切正常"。**
> 补充：`DuplicateKeyException` 是 `RuntimeException` 的子类，而 `@Transactional` 默认只对 `RuntimeException` 回滚。

## 四、工作约定

1. **改完代码 → ⏹ 停止 → ▶ 启动**（不信 IDEA 的热重载）
2. **"做完了"的标准是"我看到结果了"**，不是"我执行了"
3. **每个阶段做完就提交 Git**，commit message 用 `feat:` / `fix:` 开头，标题简短、细节放 body
4. **每个功能写完，先自己想（手算一遍），再让我验证**
5. **遇到 500：先看堆栈里的 `### Cause:` 和 `### SQL:`，再看第一个 `com.zjc` 行**
6. **算法每天 1 题**（力扣「面试经典 150 题」），三遍法：自己想 20 分钟 → 合上答案重写 → 第二天再做一遍
7. **命名规范**：类名大驼峰（`ReservationSlot`）、方法/变量小驼峰（`openSlot`）、数据库列下划线（`open_slot`）
